# 維護流程（給維護者與接手的 AI 分頁）

這個 repo 是從一個「發布工作區」產生的：工作區的上一層放著建置、掃描、上架用的腳本（`tools/`、`qa/`）與專案頁原始檔（`site/`），這些不進公開 repo。下面的指令都在**發布工作區根目錄**執行。

## 1. 追加一筆製作紀錄（最常用）

零件到貨、外殼印好、試裝結果、要求調整……都用同一行：

```sh
# 先本機演練：追加 → 重建頁面 → 去識別化掃描 → 和上次上架的頁面比對，不碰線上專案頁與 GitHub
sh tools/journal_append.sh "now" "切片／機構工程師 bot" "白盤印好：上殼四角翹 0.2 mm，合格。"

# 確認比對結果只有製作紀錄變動後，同一行加 --go 再跑一次（同一筆不會重複追加）
sh tools/journal_append.sh --go "now" "切片／機構工程師 bot" "白盤印好：上殼四角翹 0.2 mm，合格。"
```

- **時間**：`now`，或寫成 `11/17（二）14:05`、`11/17（二）約 14:00`（臺灣時間、含星期；不確定就加「約」，不要編）。
- **角色**：產品、採購、接線、機構、切片、韌體、軟體、AI，或分頁／agent 的通稱。**不要放私人帳號、購買通路與交易資訊、內部主機名。**
- **內容**：可多行。失敗與修正用列點寫：
  ```
  黑盤試裝底座。
  - 失敗：底座太緊，放不到底。
  - 修正：修掉第一層象腳後可放到底。
  ```
- 狀態誠實：還沒在實機上做過的事，寫「尚未實機驗證」，不要寫成已量測、已通過。

`--go` 會依序：

1. 確認線上專案頁和上次上架的版本一致，並備份上次的 zip。
2. 用**同一個工具 id** 做加法更新（只換頁面 zip 與自製封面；工具網址不變）。
3. 確認線上的製作紀錄已是新版。
4. 只 commit `docs/JOURNAL.md`，push 到 `main`（不 force push）。

任何一步失敗就停下來，不會半套：例如頁面除了製作紀錄還有別的變動、掃描有命中、線上版本和備份對不上。

> 線上專案頁前面有 CDN，css／js 會快取 24 小時（index.html 不快取）。建置時會在 index.html 引用的 css／js 後面加上內容雜湊（`?v=…`），內容一變網址就變，所以新紀錄更新後馬上看得到。3D 模型（GLB）與圖片沒有加版本號：換外殼模型時檔名要換，或接受最多 24 小時的舊快取。

## 2. 其他變更（韌體、外殼、頁面內容）

不要用 `journal_append.sh`，它只允許製作紀錄變動。流程：

1. 改 repo 或專案頁原始檔；外殼有新版就把交件檔放進 `cad-drop/`，跑 `sh tools/refresh_cad.sh`（同步 `cad/`、轉 GLB、更新列印順序、Release 附檔、重打包、掃描）。
2. 重跑測試：韌體 `sh firmware/test/run_tests.sh`、伺服器 `python3 -m unittest discover -s server/tests`、頁面 QA。
3. 去識別化掃描 0 命中才 commit／push；頁面更新同樣走「同一個工具 id 的加法更新」，更新前備份、更新後驗證。
4. 在製作紀錄補一筆說明這次改了什麼。

## 3. 去識別化（每次 commit、push、上架前）

掃描範圍：repo（含 git 歷史）、頁面 zip、封面、Release 附檔（G‑code、STEP、STL 壓縮檔）、圖片 metadata。命中只印「檔:行＋規則名」，不印內容。允許公開的只有：Onshape 公開文件連結、參考專案與姊妹專案的頁面連結。
